# Smart In-Cabin Energy & Incident Automation System
智慧車載電力與事件自動化模擬系統（期末專案企劃書）

主題範疇：Smart Home Energy & Comfort Automation (Vehicle In-Cabin Adaptation)
提案類型：網頁互動式模擬平台

> 本文件為原始提案 PDF 的逐字轉錄，作為功能需求的唯一依據。

## 1. Problem Description（問題描述）

現代車載電器（前後行車記錄器、電子後視鏡、中控音響、儀表螢幕、空調、座椅加熱、車用插座等）通常獨立運作，缺乏跨區域與跨裝置的整合調配，面臨三大核心問題：

- **突發安全事件反應分散**：遭遇車前/車後撞擊、救護車接近、盲區換道衝突或續航不足時，駕駛需分心手動操作多種介面，易錯失救援通報時機或遺失關鍵影像證據。
- **車載電力資源受限**：車輛供電主要由發電機（預設 1000W）供給，在寒冷環境同時開啟大功率空調、除霧、座椅加熱與逆變器時極易超載，恐導致電瓶虧電或造成核心安防系統供電。
- **環境舒適度需智能動態連動**：車外氣溫波動需頻繁手動調整高功耗的空調與除霧，需納入全車電力預算統一調配。

本系統將車艙視為「移動的智慧家庭」，建構一套有限電力下的動態負載管理與事件驅動連動架構，兼顧安全保護與乘員舒適性。

## 2. Target Users（目標受眾）

- **車輛駕駛 (Driver)**：獲得主動聽視覺警示（盲區閃爍、救護車避讓、加油站推薦），並在撞擊時享有自動存證與 110/119 通報支援。
- **車內乘客 (Passenger)**：正常使用座椅加熱與車載充電插座，在電力超載時獲得明確的延後/降載提示。
- **系統測試/審核人員 (TA / Reviewer)**：透過專屬 Web 模擬面板注入事件、調整氣溫/電力、控制模擬時鐘並檢視日誌以驗證可重現性。

## 3. Project Scope（專案範疇）

**In Scope（系統包含範圍）：**

- 支援車載各分區（Zone）與各級設備之拓撲規劃與狀態監視（Normal, Warning, Emergency, Standby, Shed, Deferred, Fault）。
- 電力預算管理：以各設備瓦數（W）加總計算負載率，落實 P0–P3 階梯式自動降載、延後啟動與恢復機制。
- 六大重大行為：雙向撞擊存證與 110/119 報警、救護車避讓、盲區變道、低里程加油站推薦、電力超載管理、氣溫舒適度調節。
- 提供 TA 模擬測試控制台、確定性模擬時鐘（可單步/暫停）與系統一鍵重置（Reset）。

**Out of Scope（不包含範圍）：** 實體車輛 CAN-bus/硬體接線；真實 4K 影片編碼與真實電信通話撥號（以模擬進度條與視窗呈現）；商用導航 API 與複雜電瓶化學特性。

## 4. Initial Specification of Important Behaviors（重大行為初始規格）

### 行為 1：前/後撞擊事故存證、自動報警 (110/119) 與緊急電力保留

- **觸發條件**：前碰撞或後碰撞傳感器回報衝擊值 ≥ 4.0g。
- **連鎖反應**：
  1. 系統升為 CRITICAL_EMERGENCY，儀表跳出紅色事故警告並標記碰撞方向（前側/後側）。
  2. 前後記錄器切換至 EMERGENCY_LOCK，受撞擊側優先執行 UPLOADING（10 秒完成 100%）。
  3. 啟動 10 秒 eCall 倒數，畫面提供選擇撥打 119（救護）或 110（警政）（亦可取消談判），倒數結束轉為 CONNECTED 並發送座標與撞擊方向。
  4. 觸發緊急電力保留，強制關閉 P2、P3 設備與音響以保障救援通訊電力。

### 行為 2：後方救護車避讓提示

- **觸發條件**：音訊傳感器偵測到緊急車輛鳴笛聲並解析出方位。
- **連鎖反應**：娛樂音響切換為 MUTED（保存原音量）；中控儀表跳出「[方位] 有救護車，請注意避讓」；笛聲消失後音響與介面自動恢復原狀態。

### 行為 3：盲區變換車道衝突警告

- **觸發條件**：盲區雷達回報 DETECTED 且同側方向燈為 ACTIVE。
- **連鎖反應**：該側後視鏡 LED 快速閃爍（FLASHING），中控蜂鳴器持續發出警示音。關閉方向燈或車輛離開後立即解除；若僅盲區有車但未打燈則 LED 恆亮不鳴響。

### 行為 4：剩餘里程過低與加油站導航推薦

- **觸發條件**：行車電腦回報續航里程 ≤ 30 km（≤ 10 km 升級為紅色 CRITICAL_RANGE）。
- **連鎖反應**：自動以剩餘里程 × 0.9（保留 10% 餘裕）篩選可抵達之加油站 POI，於中控螢幕依距離排序顯示站名、距離、預估抵達消耗，並提供模擬導航設定。

### 行為 5：車載電力超載與動態負載管理 (Load Shedding)

- **觸發條件**：總功率需求超過發電機容量（負載率 > 100%）。
- **卸載順序**：
  1. 關閉 P3 逆變器插座與音響；
  2. 依序調降 P2 座椅加熱（後座→副駕→駕駛，每次降 1 檔至 0 檔）；
  3. P1 空調每次調降 1 檔（最低保留 1 檔，除霧不關閉）；
  4. P0 永不卸載。
- 若容量回升則依反向順序自動恢復或解除 DEFERRED（延後啟動）設備。

### 行為 6：車外溫度與座艙舒適度連動

- **觸發條件**：車外溫度變化（測試範圍：-20°C 至 45°C）。
- **連鎖反應**：自動模式下依溫差動態調節空調檔位；溫度 ≤ 3°C 自動開啟後擋風除霧（180W），溫度回升至 > 5°C 自動關閉，功耗隨時回饋至電力預算。

## 5. Technology Stack & Execution（技術選型與執行方式）

採用 **Node.js 20+ (Express)** 搭配純 JavaScript 狀態機與規則引擎，前端採 **HTML5 / CSS / JavaScript (REST + Server-Sent Events)** 即時更新儀表板與 TA 測試控制台。資料以內建 JSON 檔初始化，內建 `node:test` 針對六大行為進行可重現之自動化測試。
