# TA 驗收操作指南

本文件說明如何在網頁上逐項驗證提案的六大行為與系統功能。每一步都寫出要按的按鈕與應該看到的結果。

## 開始之前

1. 執行 `npm install`，再執行 `npm start`，開啟 http://localhost:3000/ 。
2. 畫面分成四塊：座艙儀表、電力預算、車輛區域與設備、右側的 TA 模擬操作台與車載日誌。
3. 頁首有系統等級、模擬時鐘與「警示音」按鈕。要聽到聲音時，先按一次「警示音」開啟。
4. 想逐秒檢查時，先按頁首「暫停」，再用「+1 秒」「+5 秒」「+10 秒」推進。
5. 每個預設情境都會先重置狀態，再套用情境，所以可以重複執行並得到相同結果。

## 行為 1：前／後撞擊、eCall 與緊急電力保留

1. 按「暫停」，在「行為 1」輸入衝擊值 6，按「觸發後撞」。
2. 頁首系統等級變為 `CRITICAL_EMERGENCY（緊急事故）`。
3. 儀表出現紅色「後方撞擊事故（6 g）」並標示「碰撞方位：後方（後側）」。
4. 影像雲端存證顯示「受撞擊側 後行車記錄器」，前行車記錄器為 `EMERGENCY_LOCK`。按「+5 秒」後進度 50%，再按「+5 秒」為 100%。
5. 畫面左下出現「eCall 緊急通報」通話視窗，顯示 10 秒倒數與三個按鈕：撥打 119、撥打 110、我沒事，取消通報。
6. 驗證三種結果（每種都先按「解除事故」再重新觸發）：
   - 按「撥打 110（警政）」：視窗變為「已連線 110（警政）」，列出已傳送的 GPS 座標、撞擊方向與衝擊值。
   - 不按任何按鈕，按「+10 秒」：自動撥打「119（救護）並通報 110（警政）」並連線。
   - 按「我沒事，取消通報（誤觸）」：視窗顯示「駕駛已取消通報」。
7. 電力預算的「負載管理決策」列出被「緊急電力保留」卸載的 P2、P3 設備與音響。
8. 衝擊值輸入 3 再觸發：日誌記錄輕微碰撞，不啟動事故流程。
9. 在「設備故障注入」把「後碰撞傳感器」設為故障，再觸發後撞：日誌記錄未被偵測，系統等級不變。

日誌應依序出現：碰撞傳感器回報、受撞擊側優先上傳、緊急電力保留、eCall 倒數開始、`系統等級：NORMAL → CRITICAL_EMERGENCY`。

## 行為 2：救護車避讓

1. 載入情境「後方救護車接近」。
2. 音訊傳感器顯示「笛聲：後方」，音響顯示「🔇 靜音（保留音量 5）」。
3. 儀表出現「後方有救護車，請注意避讓」。若已開啟警示音，會聽到提示音。
4. 按「救護車離開」：音響恢復「音量 5」，警示消失。
5. 把「音訊傳感器」設為故障後按「周遭出現救護車」：音響不靜音，日誌記錄「音訊傳感器故障，未被偵測」。排除故障後立即偵測並靜音。

## 行為 3：盲區變換車道

1. 按「左盲區有車」：盲區監測卡顯示左側雷達 `DETECTED`、LED「恆亮」，蜂鳴器「靜止」。
2. 方向燈按「◀ 左」：方向燈顯示 `ACTIVE（◀ 左）`，左側 LED「快速閃爍」，蜂鳴器「🔊 持續警示音」，儀表出現紅色「左側盲區有來車」。
3. 方向燈按「關」，或再按一次「左盲區有車」讓車輛離開：閃爍與警示音立即解除。
4. 方向燈打右邊：左側只維持恆亮，不鳴響。
5. 把「左盲區雷達」設為故障：左側盲區輔助失效，不再警示。把「左電子後視鏡」設為故障：儀表與蜂鳴器仍會警示。

## 行為 4：低里程與加油站推薦

1. 在「行為 4」按「25」：儀表出現「剩餘里程過低（25 km）」。
2. 推薦表只列出距離 ≤ 25 × 0.9 = 22.5 km 的加油站，依距離排序，顯示站名、距離、預估抵達消耗與抵達後剩餘里程。超出範圍的站收在「超出可抵達範圍」摺疊區。
3. 按任一站的「設定導航」：該列標示「導航中・取消」。按它或操作台的「取消導航」可以取消。
4. 設定導航後把里程改成較小的值，讓該站超出範圍：日誌記錄「已超出可抵達範圍，自動取消導航」。
5. 按「8」：警示變為紅色「剩餘里程極低」，行車電腦為 `CRITICAL_RANGE`，系統等級為 `CRITICAL`。
6. 里程回到 33 km 警示仍在，超過 35 km 才解除。推薦表下方與操作台都寫出這條遲滯規則。
7. 把「行車電腦／里程感測」設為故障（或在配置頁刪除它）再回報 25 km：儀表顯示「里程資訊無法取得」，不顯示推薦表，也不會出現「建議聯絡道路救援」。修復後立即恢復推薦。

## 行為 5：電力超載與負載管理

1. 載入情境「寒流夜間長途（電力超載）」。
2. 電力預算顯示「設備需求（管理前）1296 W・129.6%」與「負載率 > 100%：啟動負載管理」。
3. 實際用電降為 966 W。P3 的逆變器與後座螢幕為「延後啟動」，音響為「已卸載」，座椅加熱維持運作。
4. 載入情境「寒流＋發電機故障（容量 400 W）」：三個座椅加熱依後座、副駕、駕駛逐檔降到 0，空調降到 2 檔，除霧不關閉。
5. 按「發電機故障中（點擊恢復）」：設備依反向順序自動恢復。
6. 載入情境「電力危急（容量 200 W）」：狀態為「電力危急」，系統等級 `CRITICAL`，P0 安全設備維持供電。

## 行為 6：車外溫度與舒適度

1. 拖動「行為 6」溫度滑桿到 −6 °C：空調自動調為暖氣 5 檔，除霧自動開啟（180 W），電力預算即時增加。
2. 日誌出現「空調系統：自動依溫差調節 1 → 5 檔」與「車外 -6 °C ≤ 3 °C：自動開啟後擋風除霧」。
3. 拉到 4 °C 除霧仍開啟，拉到 6 °C 才自動關閉。
4. 手動調整空調檔位後，自動模式關閉，溫度變化不再改變檔位。

## 系統功能

- **分區狀態**：每個區域卡片右上角顯示區內最嚴重的設備狀態，例如撞擊時車頭感知區為「緊急」。
- **配置**：在「區域與設備配置」頁新增、修改、刪除區域與設備，或調整優先等級與卸載順序。
- **重置**：「重置狀態」保留配置並回到初始狀態；「恢復原廠配置」從內建 JSON 重新載入。
- **日誌**：可依類別篩選，並用「匯出 JSON」「匯出 CSV」下載完整日誌。執行相同情境兩次，暫停時鐘並以相同步驟操作，匯出內容會一致。
- **自動化測試**：執行 `npm test`，涵蓋六大行為與系統功能。
