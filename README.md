# Smart In-Cabin Energy & Incident Automation System

智慧車載電力與事件自動化模擬系統。

## 執行方式

需求：Node.js 20 以上。

```bash
npm install
npm start
```

- 中控儀表＋TA 模擬操作台：http://localhost:3000/
- 區域與設備配置：http://localhost:3000/config.html

更換連接埠：`PORT=8080 npm start`（Windows PowerShell：`$env:PORT=8080; npm start`）

伺服器預設只接受本機（127.0.0.1）連線，因為 API 沒有登入驗證。要讓手機或另一台電腦開啟儀表時，改用 `HOST=0.0.0.0 npm start`（Windows PowerShell：`$env:HOST="0.0.0.0"; npm start`），再以這台電腦的 IP 連線；同一網路的人都能操作，DEMO 結束後請關閉。

自動化測試：

```bash
npm test
```

TA 驗收步驟請看 [docs/TA_GUIDE.md](docs/TA_GUIDE.md)，提案逐條對照請看 [docs/REQUIREMENTS_TRACE.md](docs/REQUIREMENTS_TRACE.md)。

## DEMO 步驟（約 10 分鐘）

這份是展示用的精簡流程，每一步只看最關鍵的結果；逐項驗收與完整的預期日誌請看 [docs/TA_GUIDE.md](docs/TA_GUIDE.md)。

**準備**

1. `npm install`，再 `npm start`，用瀏覽器開啟 http://localhost:3000/ 。另開一個分頁 http://localhost:3000/config.html 備用。
2. 按頁首「警示音」開啟聲音（瀏覽器規定要先點一次才能發聲）。
3. 按頁首「暫停」，讓模擬時鐘停住；之後用「+1 秒」「+5 秒」「+10 秒」推進，每次 DEMO 結果都相同。
4. 每個預設情境按鈕都會先重置狀態再套用；不用情境時，先按 TA 操作台的「重置狀態」。

**行為 1：撞擊、eCall 與緊急電力保留**

1. 按情境「前方撞擊（6.0 g）」：頁首系統等級變為 `CRITICAL_EMERGENCY（緊急事故）`，儀表出現紅色「前方撞擊事故（6 g）」；前行車記錄器 `UPLOADING`、後行車記錄器 `EMERGENCY_LOCK`；左下角跳出 eCall 通話視窗，10 秒倒數，蜂鳴器鳴響；「後座娛樂螢幕（左）」與「娛樂音響」被「緊急電力保留」卸載（右螢幕情境沒有開啟，維持待機）。
2. 按「撥打 119（救護）」：視窗變為「已連線 119（救護）」，列出已傳送的 GPS 座標、撞擊方向與衝擊值。
3. 也可以改成不按任何按鈕，按兩次「+5 秒」：上傳到 100%，倒數結束後自動撥打「119（救護）並通報 110（警政）」。
4. 按「解除事故」。

**行為 2：救護車避讓**

1. 按情境「後方救護車接近」：音響顯示「🔇 靜音（保留音量 5）」，儀表出現「後方有救護車，請注意避讓」。
2. 按「救護車離開」：音響恢復音量 5，提示消失。

**行為 3：盲區變換車道**

1. 按情境「左側盲區有車＋打左方向燈」：左側 LED「快速閃爍」，蜂鳴器「🔊 持續警示音」，儀表紅色「左側盲區有來車」，系統等級 `CRITICAL`。
2. 方向燈按「關」：閃爍與警示音立即解除，LED 回到「恆亮」（車還在盲區，但沒有要變換車道）。

**行為 4：低里程與加油站推薦**

1. 按情境「剩餘里程 25 km」：儀表出現「剩餘里程過低（25 km）」，推薦表只列出 25 × 0.9 = 22.5 km 內可抵達的加油站，依距離排序。
2. 按任一站的「設定導航」，再在操作台按「8」：警示變為紅色「剩餘里程極低」，原本的導航目標若超出範圍會自動取消並寫入日誌。

**行為 5：電力超載與負載管理**

1. 按情境「寒流夜間長途（電力超載）」：電力預算顯示「設備需求（管理前）1296 W・129.6%」，依 P3 → P2 → P1 順序處置後實際用電 966 W；逆變器與後座螢幕「延後啟動」，音響「已卸載」，P0 安全設備不受影響。
2. 按情境「寒流＋發電機故障（容量 400 W）」：三個座椅加熱逐檔降到 0，畫面顯示「已卸載」、0 W（檔位滑桿仍保留原本的 3 檔設定）；空調「降載 5→2 檔」；後擋風除霧照常 180 W，不關閉。
3. 按「發電機故障中（點擊恢復）」：容量回到 1000 W，座椅加熱回到 3 檔、空調回到 5 檔，回到第 1 步的超載狀態（實際用電 966 W，P3 仍延後或卸載）。

**行為 6：車外溫度與舒適度**

1. 按「重置狀態」，把「行為 6」溫度滑桿拉到 −6 °C：空調自動調為暖氣 5 檔，除霧自動開啟（180 W），電力預算即時增加，日誌寫出每次自動調節。
2. 拉到 4 °C 除霧仍開啟，拉到 6 °C 才關閉（遲滯，避免反覆開關）。

**系統功能（時間夠再展示）**

- **故障注入**：按「重置狀態」，在「設備故障注入」選「左盲區雷達」按「注入故障」，再在 TA 操作台按「左盲區有車」與方向燈「◀ 左」（不要按情境按鈕：情境會先重置狀態，故障也會一起清除）。儀表只提示「左側盲區輔助失效」（系統等級 `WARNING`），LED 熄滅、蜂鳴器靜止。按「排除」後立即恢復閃爍、鳴響與紅色警示。
- **eCall 故障**：撞擊倒數期間注入「緊急通報模組 (eCall)」故障：視窗顯示自動通報中斷，蜂鳴器鳴響，直到按「我知道了，我會自行撥打（停止蜂鳴器）」。
- **配置頁**：在 config.html 新增、修改、刪除區域與設備（刪除時確認框按「確定」）；刪除安全設備（例如左盲區雷達）後，回到儀表會出現黃色「未配置」提示。要還原時，在儀表 TA 操作台按「恢復原廠配置」，確認框按「確定」。這個動作會讓模擬時鐘恢復運轉（頁首按鈕變回「暫停」），做下一點前請再按一次「暫停」。
- **日誌與可重現性**：先確認頁首按鈕顯示「繼續」（時鐘已暫停），載入同一情境、做相同操作並按「匯出 JSON」，重複一次，兩份內容一致。
- **自動化測試**：`npm test`（六大行為與系統功能，全部通過）。

## 六大行為對照

| 行為 | 觸發 | 連鎖反應 |
|---|---|---|
| 1 前／後撞擊 | `impact { g, direction: front \| rear }`，g ≥ 4.0 且該側至少一顆碰撞傳感器正常（無傳感器或全部故障則不偵測） | 系統等級升為 `CRITICAL_EMERGENCY`（頁首顯示並寫入日誌）；儀表紅色警告並標記碰撞方位；受撞擊側記錄器優先 UPLOADING（10 秒），其餘記錄器 EMERGENCY_LOCK；eCall 通話視窗 10 秒倒數，可選擇撥打 119 或 110（`selectEcall`）或取消誤觸；倒數結束未選擇則撥 119 並通報 110；CONNECTED 時傳送 GPS 與撞擊方向；P2／P3 與音響強制關閉；eCall 模組故障或未配置時通報中斷（`FAULT`），蜂鳴器鳴響到駕駛確認（`ackEcallFault`） |
| 2 救護車 | `siren { active, direction }`，且音訊傳感器正常（故障或未配置則不偵測） | 音響 MUTED（保留原音量）、儀表顯示「[方位] 有救護車，請注意避讓」、笛聲結束自動恢復 |
| 3 盲區 | 盲區雷達 `DETECTED` ＋ 同側方向燈 `ACTIVE` | 該側後視鏡 LED FLASHING、中控蜂鳴器持續警示音；僅有車未打燈 → LED 恆亮、不鳴響；關燈或車輛離開立即解除 |
| 4 低里程 | 行車電腦回報里程 ≤ 30 km（≤ 10 km 為紅色 CRITICAL_RANGE；回升至 > 35 km 才解除） | 以里程 × 0.9 篩選可抵達加油站，依距離排序顯示站名、距離、預估抵達消耗；可設定或取消導航；目標超出範圍時自動取消 |
| 5 電力超載 | 管理前需求負載率 > 100% | P3 關閉 → P2 座椅加熱逐檔降至 0（後座→副駕→駕駛） → P1 空調逐檔降至 1（除霧不關） → P0 永不卸載；容量回升反向恢復、解除 DEFERRED |
| 6 車外溫度 | `setAmbient { celsius }`（−20 ～ 45） | 自動模式依溫差調節空調檔位；≤ 3 °C 自動開除霧（180 W），> 5 °C 關閉；日誌記錄每次自動調節 |

狀態與等級：

- 設備狀態：`NORMAL`、`WARNING`、`EMERGENCY`、`STANDBY`、`SHED`、`DEFERRED`、`FAULT`。
- 分區狀態：取區內最嚴重的設備狀態（嚴重度 EMERGENCY > FAULT > WARNING > SHED > DEFERRED > NORMAL > STANDBY；空區為 STANDBY）。
- 系統等級：事故進行中為 `CRITICAL_EMERGENCY`；有紅色警示（盲區衝突、CRITICAL_RANGE、電力危急）為 `CRITICAL`；有黃色警示或安全設備（P0）故障為 `WARNING`；其餘為 `NORMAL`。

聽覺警示：頁首「警示音」按鈕開啟後，蜂鳴器發聲期間持續播放警示音，救護車與低里程提示出現時播放提示音。蜂鳴器在盲區變道衝突時鳴響；撞擊後也會在 eCall 倒數期間鳴響，提醒駕駛選擇撥打對象或取消，撥出或取消後停止。eCall 無法自動通報（模組故障或未配置）時也會鳴響，直到駕駛按「我知道了，我會自行撥打（停止蜂鳴器）」或解除事故。瀏覽器規定須由使用者點擊一次才能發聲，所以預設關閉。

設計決策（提案文字有解讀空間的部分）：

- 「受撞擊側優先執行 UPLOADING」解讀為：只有受撞擊側的記錄器上傳（10 秒），其餘記錄器進入 `EMERGENCY_LOCK` 鎖定保存、不上傳；受撞擊側記錄器故障或被移除時才改由另一台重新上傳。已上傳完成的影像不會因記錄器被移除而重傳。
- 「畫面提供選擇撥打 119 或 110」解讀為動作：選擇後立即撥打，不再等待剩餘倒數；未選擇則倒數結束自動撥打 119 並通報 110。
- 「倒數結束轉為 CONNECTED」：`ecallConnectS` 預設 0 秒（直接連線）；可在配置頁調高以模擬撥號延遲（期間狀態為 `CALLING`）。
- 倒數或撥號期間 eCall 模組故障 → 自動通報中斷（`FAULT`），模組修復後不會自動恢復通報，駕駛需手動撥打。中斷時蜂鳴器鳴響，駕駛確認後停止，避免駕駛以為已經通報。
- 安全設備（P0）在配置頁被刪除、整個功能沒有任何設備時，比照故障顯示黃色提示（例如「左側盲區輔助失效／未配置左側盲區雷達」），系統等級為 `WARNING`。行車電腦由「里程資訊無法取得」提示涵蓋。
- P3 卸載順序依各設備的「卸載順序」欄位：內建配置為冰箱、逆變器、左螢幕、右螢幕、音響（提案點名的逆變器插座與音響都在 P3 第一階段卸載；冰箱為額外加入的 P3 設備，排在最前）。可在配置頁調整。
- 受撞擊側沒有任何可用的碰撞傳感器（全部故障或未配置）時，撞擊不會被偵測。
- 感測與輸出分開建模：盲區雷達負責偵測，後視鏡 LED 與蜂鳴器負責警示。雷達故障時該側盲區輔助失效；後視鏡 LED 或蜂鳴器故障時，其餘警示（儀表、另一種輸出）照常運作。
- 救護車笛聲屬於環境狀態：音訊傳感器故障期間不會偵測；笛聲仍在時修復傳感器，會立即偵測到並靜音。
- 低里程提示有遲滯：≤ 30 km 觸發，里程回升至 > 35 km 才解除，避免在門檻附近反覆出現又消失。推薦表與操作台都會寫出這條規則，門檻可在配置頁調整（`lowRangeKm`、`lowRangeClearKm`、`criticalRangeKm`）。
- 里程屬於車輛狀態，經由行車電腦（ECU）取得：ECU 故障或未配置時，儀表顯示「里程資訊無法取得」，不推薦加油站，也不能設定新的導航（已設定的目標保留）。修復或重新配置 ECU 後，立即依目前里程判斷。

## API 摘要

| 方法 | 路徑 | 說明 |
|---|---|---|
| GET | `/api/state` | 目前完整狀態 |
| GET | `/api/stream` | Server-Sent Events，狀態變化時推送 |
| POST | `/api/actions` | 觸發事件／操作，body 為 `{ "type": ..., ... }` |
| GET | `/api/log?format=json\|csv` | 匯出完整日誌（最多保留 2000 筆）；預設 JSON，其他格式回 400 |
| GET | `/api/config` | 區域、設備與系統參數 |
| POST / PUT / DELETE | `/api/zones[/:id]` | 區域 CRUD |
| POST / PUT / DELETE | `/api/devices[/:id]` | 設備 CRUD |
| PUT | `/api/settings` | 更新系統參數 |

`/api/actions` 支援的 `type`：`impact`（`g`、`direction`）、`selectEcall`（`service`: `119` / `110`）、`cancelEcall`、`ackEcallFault`、`clearIncident`、`siren`、`blindSpot`、`turnSignal`、`setRange`、`navigate`、`cancelNavigation`、`setCapacity`、`setAlternatorFault`、`setAmbient`、`setDevice`、`setFault`、`clock`（`pause` / `resume` / `step`）、`tick`、`reset`、`factoryReset`、`scenario`。
